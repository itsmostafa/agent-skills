# readme-marketer

**Rewrite a technical README so a visitor understands the project in five seconds and gets a first result in three steps.** The technical content stays; the order and framing change.

## The problem

Most READMEs are written by the person who built the project, for the person who built the project. They open with implementation details, list features as internals ("uses Redis cache"), and put the install command below the architecture notes. A visitor who cannot tell what the project does for them leaves before they scroll.

## What you get

- **A hook above the fold.** The project name, a one-sentence value proposition (what problem it solves and for whom), badges for CI status, release version, and license, and a visual anchor such as an ASCII diagram or a slot for a GIF.
- **A "Why This Exists" section.** The pain with current alternatives, then how this project removes it.
- **A fast path to the first result.** A one-line copy-paste install command and a minimal three-step usage snippet.
- **Features framed as outcomes.** "Uses Redis cache" becomes "sub-millisecond query responses with zero config".
- **A next step for the reader.** Contribution guidelines, a star-history link, or a community badge.

The main README of this repository was written with this skill.

## How to use it

The skill loads on its own when you ask for a README rewrite:

```text
Rewrite this README so new visitors understand what the project does and how to try it.
```
